# Mentor Meeting Summary

- Date: July 26th, 2026

## Main Discussion

- The meeting focused on preparing the final project presentation and evaluation.
- The mentor emphasized that the presentation should provide an honest analysis of the project rather than presenting it as an entirely successful product.
- We discussed approaches for organizing the presentation, supporting the analysis with project data, and highlighting lessons learned.

## Mentor Feedback

### Focus on Project Analysis

- The presentation should emphasize:
  - Major project issues.
  - Why they occurred.
  - How they affected the project.
  - What could have been done differently.
- Analysis should be supported by project metrics and evidence rather than opinions.

### Improve Presentation Structure

- Instead of presenting each practice area independently, organize the presentation around the project's major challenges (e.g., migration), discussing each issue from multiple software engineering perspectives.
- A timeline or issue-based narrative was recommended to better connect planning, tracking, configuration management, requirements, and other practice areas.

### Use Data to Support Conclusions

- Collect project metrics that demonstrate:
  - Planned vs. completed work.
  - Estimated vs. actual effort.
  - Sprint progress.
  - Team workload distribution.
- Explain how these metrics could have revealed project problems earlier and informed better decisions.

### Be Honest and Objective

- Avoid hiding project weaknesses or presenting an overly positive narrative.
- The mentor stressed that objective analysis is more valuable than trying to justify mistakes.
- Team performance should be discussed using evidence and metrics rather than personal opinions.

### Presentation Preparation

- Create the presentation from scratch instead of reusing previous slides.
- Begin with a broad collection of ideas and supporting data before selecting the final presentation slides.
- Prepare additional backup slides containing supporting information for the Q&A session.

### Artifact Review

- Project artifacts will be reviewed before the presentation and may also be revisited afterwards.
- The presentation should complement the repository rather than attempting to cover every detail.

## Agreed Actions

- Build a new presentation focused on project analysis rather than feature demonstration.
- Organize the narrative around key project challenges and lessons learned.
- Support all conclusions with metrics and repository evidence.
- Prepare backup slides for detailed questions.
- Share a draft presentation with the mentor for review before the final presentation.
